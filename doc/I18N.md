# Chinese localization

The board UI and CLI support English and Simplified Chinese. Translate product
copy at display boundaries; retain command names, flags, routes, database values,
API fields, MIME types, CSS classes, credentials, and user-authored content.
Provider, model, font and protocol names retain their official spelling.

## Board UI

English source messages live in `ui/src/i18n/locales/en.json`; Simplified Chinese
messages live in `zh-CN.json`. Their keys must match exactly. Other language
packs remain partial and fall back to English. The language picker offers packs
that meet the coverage threshold, plus English.

The initial language comes from the saved `paperclip.locale` preference, then
browser languages, then English. Chinese browser tags such as `zh` and
`zh-Hans-CN` resolve to Simplified Chinese. The active language controls date
formatting and the document's `lang` and `dir` attributes.

Changing language saves the preference and reloads the page. This also refreshes
labels initialized in module-level option arrays. Keep drafts saved before
switching languages.

Use the translation hook in React components and the plain helper elsewhere:

```tsx
import { t, useTranslation } from "@/i18n";

// Named parameters let Chinese sentences reorder their contents.
t("zhCore.connectApp", { app: providerName });
```

Do not insert hooks into callbacks, event handlers or plain utilities. Avoid
splitting sentences around variables or appending English plural suffixes. Use
whole messages and i18next's `_one` / `_other` forms with `count` instead.

`ui/src/lib/display-labels.ts` maps known status, role and other enum values to
display labels. The original enum remains the identifier. The `raw` domain
retains a caller's original English spelling; Chinese still uses its display
label. Unknown extension values remain unchanged.

`translateDisplayMessage` translates known system messages from APIs, adapter
schemas and the Apps catalog. It matches complete English messages, including
named template parameters, and preserves unknown messages. Apply it only to
system display fields, never to arbitrary task text or user titles. API errors
retain `rawMessage`, status and response bodies for classification and recovery.
Use these original values when deciding what an error means.

`display-parameters.json` lists specific server templates whose parameters are
English inflections or fixed system choices. Only the listed parameter values
are replaced in Chinese; names, paths and other parameters remain unchanged.
This prevents export notices from displaying an English `s` or `were` suffix.

## CLI

`cli/src/i18n.ts` has no additional runtime dependency. The preference order is
`PAPERCLIP_LOCALE`, `LC_ALL`, `LC_MESSAGES`, `LANG`, then English. Set
`PAPERCLIP_LOCALE=zh-CN` for Chinese or `PAPERCLIP_LOCALE=en` for English.

Use `tCli("English {{name}}", { name })` for human help, prompts, diagnostics and
console messages. The English source sentence is the key in
`cli/src/locales/zh-CN.json`. Use `translateCliDisplayMessage` for known complete
server error messages. Preserve machine output and use `rawMessage` when
serializing or classifying errors. Do not intercept console output globally.
Keep internal error text and markers used by recovery logic in their original
form, and translate the final human diagnostic instead.

## Terminology

| Source | Chinese | Context |
| --- | --- | --- |
| agent | 智能体 | Assigned AI worker |
| company / organization | 组织 | Workspace and access boundary |
| board | 管理端 | Human operator context |
| issue / task | 任务 | Work item |
| backlog | 储备任务 | Work not yet queued |
| todo | 待办 | Queued work |
| routine | 例行任务 | Recurring work |
| worktree | Git 工作树 | Isolated Git checkout |
| watchdog | 监控者 | Task progress supervision |
| artifact | 产出 / 产出文件 | Work products and their files |

Use the sentence's product context when a term has multiple meanings. For
example, the new-task dialog uses “分配给” and “所属” for its assignee and project
fields instead of translating “For” and “In” in isolation.

## Validation

Run `pnpm check:i18n` to check UI catalog parity, referenced literal translation
keys, raw JSX text, templates and conditional display expressions, accessible
attributes, and misplaced translation hooks. It also checks CLI message
placeholders, referenced source
messages, human console output and command help.
Its explicit exceptions cover audited brands, technical examples and shortcuts.
It is a source check, not proof that every external provider response is localized.

Locale validation additionally enforces identical interpolation placeholders,
length bounds, and restrictions on unexpected HTML and URLs. Do not weaken
validation to hide a missing variable. Keep example code and command parameters
verbatim.

Tests cover language negotiation, preferences, system-message interpolation,
Chinese error recovery, and preservation of API headers, response bodies and
user content. Run the relevant UI and CLI suites after changing copy. Verify the
English interface too: missing spaces and changes in capitalization can break
accessible names and existing workflows.

For a repository hand-off run the prescribed typecheck, test and build commands,
as well as `pnpm check:token-gates`. Full runner checks require the Rust toolchain
in addition to Node and pnpm; report unavailable checks explicitly.
